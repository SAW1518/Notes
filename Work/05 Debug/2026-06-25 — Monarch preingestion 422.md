## How far it got

1. Pre-ingestion event received (webhook → `202 Accepted`, async processing).
2. Routed to the **MONARCH** orchestrator.
3. Feature toggle `MONARCH_AUTOMATIC_INGESTION` → `true` (read from Redis).
4. PDP metadata fetched (mocked, `usePdpMockApi: true`).
5. Polyphonic identity resolved against `tenant-mgmt-v2` → OK.
6. PDP metadata validation → **passed**.
7. File upload starts (`filesCount: 1`).
8. `POST` to `jnj-media-mgmt-svc/api/v1/files/managed-remote-upload` → **422** 💥

So: the problem is **not** auth, not feature flags, not the metadata. It's in what gets sent to media-mgmt on the upload.

## Where to pick up next time

- Inspect the exact `managed-remote-upload` body — a 422 is a validation error, so there's a field media-mgmt won't accept.
- The file declares `sizeBytes: 21474836480` (20 GB) pointing at the mock MP4 on CloudFront. Suspicious: check whether there's a size limit.
- Since it's *non-retryable*, the message is lost. To retry you have to republish it → [[Kafka — kcat and consumer groups]].
