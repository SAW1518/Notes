# JavaScript

## let vs var vs const

The principal difference between `var`, `let` and `const` is the **scope**.

| | `var` | `let` | `const` |
|---|---|---|---|
| Scope | **Function** | Block `{ }` | Block `{ }` |
| Redeclare | Yes | No | No |
| Reassign | Yes | Yes | **No** |
| Hoisting | `undefined` | `ReferenceError` (TDZ) | `ReferenceError` (TDZ) |

`const` is a constant: once it is defined we can not redeclare it or reassign it. But we **can mutate** it if it is an object or an array:

```js
const user = { name: "Ana" };
user.name = "Luis";        // ✅ we mutate the content
user = { name: "Luis" };   // ❌ TypeError: Assignment to constant variable
```

> [!danger] Correction: `var` is not global
> The original said that "`var` has a global scope". That is **not** true: `var` has **function scope**. Inside a function it stays inside that function.
> ```js
> function test() {
>   if (true) { var v = "hello"; }
>   console.log(v);  // "hello" ← it escapes the IF, but NOT the function
> }
> test();
> console.log(globalThis.v);  // undefined ← it is NOT global
> ```
> It is only global when we declare it **outside** of any function. Verified in Node ✅

> [!question] Short answer for the interview
> "`var` is function scope, `let` and `const` are block scope. `var` can be redeclared and it hoists as `undefined`; `let` and `const` are in the temporal dead zone, so they throw a `ReferenceError` if we use them before. `const` can not be reassigned, but if it is an object we can still mutate its properties."

## What is a template string (template literal)

They are strings that allow us to add JS expressions inside, and they are enclosed by back-ticks `` ` ``.

```js
const name = "Ana";
const age = 30;

console.log(`Hello ${name}, you have ${age} years`);
console.log(`Next year: ${age + 1}`);   // we can put any expression

// they also support several lines
const html = `
  <div>
    <p>${name}</p>
  </div>
`;
```

## What is the DOM

The **Document Object Model** is the representation, in the form of a **tree**, of the objects that compose the structure of a document on the web. It is the bridge that lets JavaScript read and modify the HTML and the CSS of the page.

## Call stack and task queue

In JS there is a mechanism that has the job to organize the execution time. The **call stack** executes the code, one thing at a time, and the **queues** keep the callbacks that are waiting.

## What is an event

An event can be triggered by a user action — for example clicking the mouse or tapping the keyboard — or generated by the APIs to represent the progress of an asynchronous task.

**Microtask queue** things: `.then()`, `.catch()`, `.finally()`, `await`, `MutationObserver`, `queueMicrotask`.

**Task queue** things: `setTimeout()`, `setInterval()`, `onClick`, `onKeyPress`, `click`, `scroll`, `keypress`, `mousedown`.

> [!note] The microtask queue has priority over the task queue.

## Who manages an event in JS

In the **browser** we can listen to the things that happen. The most popular way is `addEventListener`:

```js
buttonContainer.addEventListener("click", (event) => {
  console.log(event.target.value);
});
```

## What is a callback function

A callback function is a function passed into another function as an argument. That function is executed **inside** the main function, normally when something finishes.

```js
function greet(name, callback) {
  console.log("Hello " + name);
  callback();               // ← here we execute the callback
}

greet("Ana", () => console.log("Finished"));
```

## Difference between `==` and `===`

- **`===`** (strict) checks that the value **and** the type are equal. It does **not** convert anything.
- **`==`** (loose) converts the types before comparing (this is called **coercion**), so it only compares the value.

```js
1 === "1";   // false  ← different type
1 ==  "1";   // true   ← it converts "1" to 1
```

> [!warning] The classic traps
> ```js
> null == undefined;   // true  ← but null === undefined is false
> "" == 0;             // true
> "0" == false;        // true
> [] == false;         // true
> NaN === NaN;         // false 😱  (use Object.is or Number.isNaN)
> ```
> All verified in Node ✅. The rule in real projects: **always use `===`**. The only common exception is `x == null`, to check `null` and `undefined` at the same time.

## What are lambda or arrow functions

An arrow function is a concise form of a function expression and it does **not** bind its own `this`, `arguments`, `super` or `new.target`.

```js
const sum = (a, b) => a + b;
```

> [!tip] Why does the `this` matter?
> An arrow function takes the `this` of the place where it was **written**, not of the place where it is **called**. This is why they work well inside a `setTimeout` or a `map`, but they can **not** be used as methods of an object when we need the `this` of the object.

## What is a pure function

A function is pure when it complies with **two** conditions:

1. With the **same input** it always returns the **same output**.
2. It does **not** have **side effects**: it does not modify anything outside of it.

```js
// pure ✅
const sum = (a, b) => a + b;

// NOT pure ❌ (it depends on something external)
let tax = 0.21;
const price = (p) => p * (1 + tax);

// NOT pure ❌ (it modifies the parameter = side effect)
const addItem = (arr, item) => { arr.push(item); return arr; };

// pure version ✅
const addItem = (arr, item) => [...arr, item];
```

> [!danger] The original was missing half
> It only said "it is not affected by external code". The second part is as important: **no side effects** (do not modify parameters, do not write in the DOM, do not call an API, do not use `console.log`).

## What is hoisting

When JS analyses the code, before executing it, it **registers** the declarations of the variables and the functions in the memory of that scope. This is why we can use some things before the line where they are written.

But **not everything behaves the same**:

```js
console.log(a);   // undefined      ← var exists, but it is empty
var a = 1;

console.log(b);   // ❌ ReferenceError  ← let is in the TDZ
let b = 1;

sayHi();          // ✅ "hi"        ← function declarations work
function sayHi() { console.log("hi"); }

sayBye();         // ❌ TypeError   ← function expressions do not
const sayBye = () => console.log("bye");
```

> [!danger] Correction
> The original said that when we access before the declaration "they are `undefined`". That is only true for **`var`**. `let` and `const` throw a **`ReferenceError`**, because they are in the **Temporal Dead Zone** (TDZ) until the line of their declaration. Verified in Node ✅
> And nothing really "moves to the top": that is only a way to explain it.

## How does the event loop work

It is the mechanism that takes the tasks from the queues and passes them to the **call stack**, but only when the call stack is **empty**. It empties all the microtask queue first, and then it takes one task from the task queue.

> [!info] It is not part of JavaScript
> The event loop is given by the **runtime** (the browser or Node), not by the language itself.
> The complete explanation with the diagram is in [[The Best Notes of the F Word#Everything together: how JS runs the code]].

## How to get the modulo of an operation

With the operator `%`, that returns the **rest** of the division:

```js
10 % 3;   // 1   ← 10 / 3 = 3 and it is left 1
3 % 3;    // 0
10 % 2;   // 0   ← this is how we check if a number is even
```

> [!warning] With negative numbers the sign follows the first number
> ```js
> -7 % 3;   // -1  (not 2, like in Python)
>  7 % -3;  //  1
> ```
> Verified in Node ✅

## What is a promise in JS

It is an object that represents the eventual **success** or **failure** of an asynchronous process, and its resulting value.

> [!info] The complete explanation is in the other note
> See [[The Best Notes of the F Word#How do promises work?]] — the 3 states, `.then/.catch/.finally`, `async/await` and the 4 combinators.

## What are classes in JS

Classes are a way to define and create objects, with a more structured and object-oriented approach.

```js
class Animal {
  constructor(name) { this.name = name; }
  speak() { console.log(`${this.name} makes a sound`); }
}

class Dog extends Animal {
  speak() { console.log(`${this.name} barks`); }
}
```

> [!important] They are syntactic sugar
> Classes in JS are **not** like classes in Java. Below, JS keeps using **prototypes**. The `class` is only a nicer syntax for the same thing. This is a very common follow-up question after [[#What is a prototype in JS]].

## What is destructuring in JavaScript

It is a feature that allows us to extract values from arrays or properties from objects, in one line.

```js
// objects
const { name, age } = user;
const { name: userName } = user;        // rename
const { city = "Madrid" } = user;       // default value

// arrays
const [first, second] = [1, 2, 3];
const [, , third] = [1, 2, 3];          // skip positions

// swap two variables without a temporal one
let a = 1, b = 2;
[a, b] = [b, a];
```

## What is a prototype in JS

A prototype is the mechanism that allows the **inheritance** of properties and methods between objects.

Every object has an internal link to another object, its prototype. When we ask for a property and the object does not have it, JS looks for it in its prototype, and then in the prototype of the prototype. This is the **prototype chain**, and it finishes in `null`.

```js
const arr = [1, 2];
// arr does not have "map", but Array.prototype has it
arr.map((x) => x * 2);
```

## Generator function

It is a special type of function that can **pause** its execution and resume it later, keeping its state.

We write it with `function*` and we pause it with `yield`:

```js
function* counter() {
  yield 1;
  yield 2;
  yield 3;
}

const gen = counter();
gen.next();   // { value: 1, done: false }
gen.next();   // { value: 2, done: false }
gen.next();   // { value: 3, done: false }
gen.next();   // { value: undefined, done: true }
```

They are used for infinite sequences, for controlling async flows (Redux Saga) and for creating custom iterators.

# React

## What is the Virtual DOM in React

The **Virtual DOM** (VDOM) is a "virtual" representation of the UI that is kept **in memory** and synced with the "real" DOM by a library, `ReactDOM`.

When the state changes, React creates a new virtual tree, compares it with the previous one (this is the **diffing**) and only touches the parts of the real DOM that really changed. Touching the real DOM is slow, so this saves a lot of work.

> [!danger] Correction
> The original said "**visual** dom". It is **virtual** DOM.

## What is a Hook in React

It is a special function in React that allows us to use React features — like the state or the lifecycle of a component — inside a **function component**, without writing a class.

> [!warning] The 2 rules of the hooks
> 1. Only call them at the **top level**, never inside an `if`, a loop or a nested function.
> 2. Only call them inside **React components** or inside **other hooks**.
> React identifies the hooks by their **order**, this is why the order can never change between renders.

## What is useEffect in React

It is a hook that allows us to execute code when the component is **mounted** and when the values of the dependency array change.

```js
useEffect(() => {
  // code of the effect
  return () => {
    // optional cleanup: it runs before the next effect
    // and when the component unmounts
  };
}, [dependencies]);
```

- `[]` → it runs **once**, after the first render.
- `[a, b]` → it runs when `a` or `b` change.
- no array → it runs on **every** render (careful with infinite loops).

> [!info] More detail in the other note
> See [[The Best Notes of the F Word#Which methods replace useEffect]] and [[The Best Notes of the F Word#useEffect vs useLayoutEffect]].

## What is useMemo in React

`useMemo()` is a hook that saves in cache the **result of a calculation**. It is useful when we have an operation that is expensive, because it avoids recalculating that value when the component re-renders.

```js
const expensiveValue = useMemo(() => heavyCalculation(a, b), [a, b]);
```

It only recalculates when `a` or `b` change.

> [!tip] useMemo vs useCallback
> - `useMemo` saves the **result** of a function → `useMemo(() => fn(a), [a])`
> - `useCallback` saves the **function** itself → `useCallback(() => fn(a), [a])`
> `useCallback(fn, deps)` is exactly the same as `useMemo(() => fn, deps)`.

## What is useRef in React

The `useRef` hook allows us to **persist values between renders**. It can also save DOM elements.

The important part: when the value of a ref changes, React does **not** do a re-render.

```js
const inputRef = useRef(null);       // to access a DOM element
inputRef.current.focus();

const count = useRef(0);             // to save a value without re-render
count.current++;
```

> [!tip] state vs ref
> If the value has to be **seen** on the screen → `useState`.
> If the value is only for us (a timer id, the previous value, a DOM node) → `useRef`.

# Redux

## What is Redux

It is a library commonly used with React to manage **global state**. It is recommended only for big applications, because it adds a lot of concepts and rules.

> [!note] Today it is lighter
> Modern Redux is used with **Redux Toolkit** (RTK), which removes a big part of the boilerplate. And for small or medium apps, the Context API, Zustand or React Query are usually enough.

## What is the Store in Redux

A JavaScript object with the responsibility of keeping the state of the application. This object is **read-only**: it can only be modified by dispatching actions.

## What is an Action in Redux

Actions are plain JavaScript objects that describe a change in the state of the application.

They must have a **`type`** property that indicates the type of the action — for example success, failed or loading — and normally they carry the data in a `payload`.

```js
{ type: "user/loginSuccess", payload: { id: 1, name: "Ana" } }
```

## What is a Reducer in Redux

A reducer is a **pure function** that receives the **current state** and an **action**, and returns the **new state**.

```js
function counterReducer(state = { count: 0 }, action) {
  switch (action.type) {
    case "increment":
      return { ...state, count: state.count + 1 };   // NEW object
    default:
      return state;
  }
}
```

Being a pure function, it can **never** mutate the state directly, call an API, or use things like `Math.random()` or `Date.now()`.

> [!danger] This was the biggest error of the note
> In the original, the answer of "What is a Reducer" was describing an **action**: "*Actions are plain JavaScript objects that describe a change...*". They are two different things:
> - **Action** = the *object* that says **what happened**.
> - **Reducer** = the *pure function* that decides **how the state changes**.
> I moved that text to [[#What is an Action in Redux]], which was missing, and I wrote the real definition of the reducer here.

## What is Dispatch in Redux

The `dispatch` function is used to **send actions** to the store. When an action is dispatched, the store calls the correct reducer(s) to update the state.

```js
dispatch({ type: "increment" });
```

## What is Middleware in Redux

It sits **between** the dispatching of an action and the moment it arrives to the reducer.

We can use it to trigger another action, to retry an API call, or to inject data into the action. The most known ones are `redux-thunk` and `redux-saga`, which are the way to handle asynchronous things in Redux.

## What are Selectors in Redux

Selectors are functions used to extract specific pieces of data from the store.

```js
const selectUserName = (state) => state.user.name;
```

The advantage is that the components do not need to know the shape of the state. If tomorrow we change the structure, we only touch the selector.

> [!tip] Memoized selectors
> With `createSelector` (of Reselect, included in Redux Toolkit) the selector only recalculates when its inputs change. This avoids re-renders that are not necessary.
