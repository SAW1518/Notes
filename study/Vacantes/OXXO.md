## My starting point

React Native up to ~2022: CLI (`react-native init`), Redux, React Navigation. My last app is [PokedexRN](https://github.com/SAW1518/PokedexRN) (January 2022 — RN 0.66, React 17, bridge architecture). Four years away from React Native, senior on React for the web. The gap is the platform, not React.

## What the interview will probe

1. **React Native today** — the New Architecture, Expo and Expo Router, and "what changed since you last used it". The four-year gap will come up; it needs a confident, concrete answer.
2. **React at senior depth** — React 19: hooks, `use`, actions, `useOptimistic`, the React Compiler, re-renders.
3. **Server state and offline** — TanStack Query, caching, a flaky mobile connection, storage.
4. **Platform-specific bugs** — something broken on Android only: how to narrow it down and fix it.
5. **Testing** — React Native Testing Library, what replaces Cypress component tests on mobile, E2E.
6. **Build and release** — EAS, over-the-air updates and their limits, store rollout.
7. **Accessibility on mobile** — roles and labels, screen readers, touch targets, dynamic type.
8. **GenAI in the product and in my workflow** — a streaming chat with the key kept on a backend, RAG, tool calling, risks; and how I use AI tools day to day.
9. **React on the web** — rendering strategies and hydration, if the role covers web as well.

## 2022 → 2026, the short version

| Area | 2022 (where I left it) | 2026 |
|---|---|---|
| Architecture | The bridge: async JSON messages between JS and native threads | New Architecture only (since 0.82): JSI, Fabric, TurboModules, Codegen, bridgeless |
| Engine | JSC by default, Hermes opt-in | Hermes by default |
| How to start | `react-native init` | A framework — Expo, as the React Native docs recommend |
| Native folders | Committed; Expo meant "eject" to customise | Generated by `npx expo prebuild` (CNG); config plugins, Expo Modules |
| Navigation | React Navigation 5/6, navigators in code | Expo Router: routes are files (`app/pokemon/[id].tsx`), `Link`, `useLocalSearchParams` |
| Server state | `useEffect` + axios, or Redux thunks | TanStack Query |
| Storage | AsyncStorage (async only) | MMKV, `expo-sqlite/kv-store` (sync APIs through JSI), `expo-secure-store` for secrets |
| Components | `TouchableOpacity`, core `Image`, core `SafeAreaView` | `Pressable`, `expo-image`, `react-native-safe-area-context` (core one deprecated since 0.81) |
| Debugging | Flipper, Chrome remote debugging | React Native DevTools |
| Builds and updates | Xcode / Gradle by hand, Fastlane, CodePush | EAS Build, Submit, Update (App Center and CodePush retired in 2025) |
| Testing | Jest + RNTL with `jest-native`, `react-test-renderer` | Jest + RNTL with built-in matchers; `react-test-renderer` deprecated; Maestro for E2E |
| Types | Flow in the template | TypeScript by default |

Versions as of October 2026: React Native 0.87 stable (August 2026), 0.88 in release candidate; Expo SDK 57 stable (RN 0.86, React 19.2), SDK 58 in beta on RN 0.88 RC.

# Still to study

**React Native platform**
- [ ] New Architecture at interview depth: JSI host objects, Fabric (concurrent rendering on native), TurboModules (lazy loading), Codegen from typed specs, what "bridgeless" removes
- [ ] Expo Router in depth: layouts, groups, typed routes, modals, deep links and universal links, auth-gated routes
- [ ] Expo Go vs development builds, prebuild/CNG, config plugins, writing an Expo Module
- [ ] Performance: FlatList tuning vs FlashList and Legend List, re-renders with the React Compiler, Reanimated 4 and Gesture Handler (UI-thread worklets), Skia
- [ ] Offline: TanStack Query persistence, mutation queues, conflict handling
- [ ] Auth: OAuth 2 + PKCE with `expo-auth-session`, tokens in `expo-secure-store`, refresh
- [ ] Monorepo web + mobile: sharing code between Expo and Next.js, `react-native-web`
- [ ] Styling options: `StyleSheet`, NativeWind, Unistyles — what each costs
- [ ] Expo UI (SwiftUI / Jetpack Compose from React) — check current status before citing it

**Rendering on the server with Expo** — verify each before citing it; it moves fast
- [ ] API Routes (`+api.ts`): a backend in the same project — where the LLM key lives

- [ ] React Server Components / Server Functions in Expo, including on iOS and Android (an RSC payload, not HTML)
- [ ] Server-driven UI: the backend sends JSON describing the screen — common in retail

**Platform-specific bugs** — the method: reproduce and narrow (OS version, device, debug vs release, Sentry) → JS or native (DevTools vs Logcat / Xcode console) → diagnose (Layout Inspector, Instruments) → fix in isolation (`Platform.select`, `.ios.tsx` / `.android.tsx`) → prevent (a test, real devices, write it down)
- [ ] The usual suspects, one example each: shadow vs `elevation`, `KeyboardAvoidingView`, Android edge-to-edge, cleartext HTTP blocked, permissions, fonts, `BackHandler` and predictive back, low-end Android devices
- [ ] One real platform bug of my own, told in four beats

**Testing**
- [ ] RNTL: `userEvent`, `getByRole` / `findBy` / `queryBy`, `renderHook`, built-in matchers; MSW or `jest.mock` for the network
- [ ] The mobile answer to Cypress component tests: RNTL for logic, Storybook for React Native (+ visual regression), device-level test runners, Maestro for E2E, Cypress/Playwright only through `react-native-web`

**Build and release**
