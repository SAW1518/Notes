# Questions

## 1. [Nordstrom · VAULT] Find the bug: POS product lookup — ❌

**Question:** A ~30-line `ProductLookup` component: a search effect that fetches with `[query]` deps, and a `window` keydown listener registered with `[]` that does `selected.push(results[0]); setSelected(selected)`. QA reports that "Enter sometimes does nothing and the cart count never moves", plus wrong results when typing fast on slow Wi-Fi. Find the bugs, rank them by store-floor impact, and write the fix.
*Follow-ups:* (1) `at(0)` vs `[0]` on an empty array, and trace `results`/`selected` inside `onKey` after the first search. (2) Does `onKey` run or not, and which values does it see? (3) Why does "so" overwrite "sock", and the fixed code.

**What I said:** "the fix could be … `selected.push(results.at(0))` to validate if the 0 of the array really exists … maybe add a method or a service" · "the second useEffect … is not executed" · "it runs but the references of the result and the state are un-updated because the deps aren't there" · "that is happening because we don't have any delay between the results and the enter events". No code.

**What was wrong or missing:** `at(0)` and `[0]` both return `undefined`, and the guard already checks the length. The listener runs with the first render's `results = []` (stale closure). `push` on the same array + `setSelected(same ref)` → `Object.is` bail-out, no re-render. The "so"/"sock" bug is two in-flight requests resolving out of order. The fix is aborting or ignoring the stale one in the cleanup, not a delay. Also missed: listener never removed, `storeId` missing from deps, no `r.ok`, unencoded query, `key={i}`.

**Missing beat:** code challenge — no working shape.

**Short answer for the interview:** "Three real bugs. The keydown listener is registered once with empty deps, so it closes over the first render's empty results and Enter does nothing. I'd move it to `onKeyDown` on the input, and any global listener gets a cleanup. The cart is mutated with `push` and set back to the same reference, so React bails out on `Object.is` and the count never updates. That needs a functional update with a new array. And the fetch effect races: a slow 'so' response can land after 'sock', so I abort the previous request in the effect cleanup. Debounce cuts the requests, but it doesn't fix the ordering."

**Study:** `React.md → ## The dependency array` · `React.md → ## First: why does a component re-render at all?` · `JavaScript.md → ### When the framing itself is wrong` · outside: react.dev "Synchronizing with Effects → Fetching data" (ignore flag / race conditions), react.dev "Separating Events from Effects" (`useEffectEvent`), StrictMode double-running effects in development.

**Related trap:** "Debounce fixes the race". It doesn't, because a slow earlier response can still arrive last. And Enter pressed while the new request is in flight adds the *previous* query's first result.

```tsx
// Reference solution
export function ProductLookup({ storeId }: { storeId: string }) {
  const [query, setQuery] = useState('');
  const [results, setResults] = useState<Product[]>([]);
  const [cart, setCart] = useState<Product[]>([]);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    if (!query) {
      setResults([]);
      return;
    }
    const controller = new AbortController();
    const url = `/api/stores/${encodeURIComponent(storeId)}/products?q=${encodeURIComponent(query)}`;

    fetch(url, { signal: controller.signal })
      .then((r) => {
        if (!r.ok) throw new Error(`HTTP ${r.status}`);
        return r.json() as Promise<Product[]>;
      })
      .then((data) => {
        setResults(data);
        setError(null);
      })
      .catch((e) => {
        if (e.name !== 'AbortError') setError('Search failed. Try again.');
      });

    return () => controller.abort();
  }, [storeId, query]);

  const addFirst = () => {
    const first = results[0];
    if (!first) return;
    setCart((prev) => [...prev, first]);
  };

  return (
    <>
      <input
        aria-label="Search products"
        value={query}
        onChange={(e) => setQuery(e.target.value)}
        onKeyDown={(e) => {
          if (e.key === 'Enter') addFirst();
        }}
      />
      {error && <p role="alert">{error}</p>}
      <ul>
        {results.map((p) => (
          <li key={p.sku}>{p.name} — {p.price}</li>
        ))}
      </ul>
      <p>{cart.length} items in cart</p>
    </>
  );
}
```
